# 周额度与今日建议

现有额度分组保持原来的位置和尺寸：左边为真实周额度剩余，右边并排显示“消耗速度”和“今日建议 / 今日超额”，重置雷达在同组下方。旧的电池、消耗时间轴、本轮已用和每日可用栏不再显示。

## 消耗速度

单位是每小时消耗多少个周额度百分点（界面 `%/h`，h 表示小时）。根据最近五分钟官方余额的实际下降计算，不把输出 token 速度换算成额度消耗，不增加接口请求。开始时至少采样一分钟；不足一分钟显示“采样中”，有效平稳余额可显示真实的 0。

以最后一条有效余额采样时间为终点，在最多 300 秒的观察区间内，用实际下降量除以区间时长再换算到一小时。窗口边界位于两个真实采样之间时按时间比例分摊这段下降。数字下方注明“近 N 分均耗”；数值只随真实新采样更新，本地时钟推进不会伪造消耗。数字变化沿用原有短过渡，不排队播放旧值。

重置时间改变、确认补额、超过三分钟的采样中断或缺失周额度窗口时重建基线，避免把旧周期消费带入新周期。一点以内的小幅非满额余额修正不重复记账。迟到样本不覆盖新样本。三分钟内的网络缓存显示“上次采样”；更旧数据或已过重置时间显示等待同步，不伪造 0。

## 今日建议与超额

建议是为了尽量撑到官方周重置而规划的额度，不是服务限额。当天第一条有效记录固定预算：按当时剩余额度乘以“距本地午夜时间 / 距周重置时间”，若重置更早则以重置为截止。之后只扣除已经观察到的真实额度下降。例：日初剩 60%，距重置五天，当天预算 12%；已消耗四个百分点，今日建议显示 +8%。

恰好用完显示 0%；预算 12%、实际消耗 20.1% 时显示 −8.1%，标题改为“今日超额”。账户实际余额仍由左侧大数字单独表示，不会变成负余额。小于 0.1% 的余量显示 +<0.1%，轻微超额显示 −<0.1%，不会把超额抹成零。内部保留原始精度。

自然日、官方周窗口改变或确认补额时重新建立预算。额度刷新后按新余额重新记账，不沿用旧周期的当天消费。重启从本地账本恢复，不重新发放预算。首次启动缺少日初记录时，从实际首次观察时间分配至午夜，不推测未观察时段。次日不重复扣除昨日超额；时间流逝本身不会增加余量。

正负状态切换即时对应新标签，不播放旧正数。两列采用开放式排版，标签、读数与说明各自对齐；数字和单位同行共用基线，单位固定在列尾，数字变化不会与单位重叠。超额使用羽化墨黑底、暖白数字和缓缓呼吸的琥珀底线，不再添加独立按钮状边框。静态偏好、暂存和低内存状态保留清楚的最终读数。

## 数据与刷新

新写入日志中的有效官方额度快照即时接入，后台每 30 秒通过已登录客户端核对，临近已知重置边界提前核对。日志写入时间不等于实际采样时间；同周期日志余额上升或旧周期回退会触发账户核实，历史重放和迟到响应不能覆盖新余额。只有账户接口确认的补额重建起点，小幅修正不清空已经观察到的消费。

短暂断网最多保留三分钟的建议，并标记上次采样；到午夜或官方重置，旧建议立即失效。内部续航估算保留以兼容既有数据，但不再占用卡片中的独立图表。

最多 400 条数字采样、周期信息和今日预算账本保存在本机 `runtime/quota-usage-history.json`。近期速度复用这些采样，不新增历史文件，不保存聊天内容或账号凭据。重置雷达的全局重置与发放重置卡分类保持独立，发卡不会诱导清空额度。
