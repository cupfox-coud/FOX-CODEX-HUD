# Privacy

The customized Windows HUD keeps local resource counts (private/working-set memory, process handles, GDI/USER objects) in its runtime status. Allocation failures and unhandled process exceptions may create `runtime/hud-errors.jsonl` with timestamp, app version, process ID, resource counts, exception types, HRESULTs and bounded stacks. Exception messages and conversation content are excluded; stacks may contain local code paths. Allocation-error logging is throttled to once per minute. The log and one rotated backup are each limited to 256 KiB. These diagnostics are never uploaded and do not replace the application's normal exception handling.

Optional application following reads same-user/session executable names and paths, never process command lines. It recognizes Codex Desktop and the shared native backend used by CLI/IDE clients, plus any exact executable paths explicitly configured by the user. A small watcher remains available after login; while no client runs it does not start the HUD, index chats or run the statistics server. Private `app-follow` files contain the installation/runtime paths, enabled state, client counts, process IDs and diagnostics. Only a HUD launched by that watcher accepts its matching owner close request. No extra network connection or Codex configuration change is made. WSL/SSH detection runs on the log host; any forwarding is explicitly set up by the user.

An optional Windows pinned binding saves only the selected conversation ID/title in `manual-binding.json`, with a separate `pinned-layout.json`. The user's explicit selection replaces accessibility tracking until unpinned; it does not change the underlying Codex conversation.

Local log measurements make no external network requests. The customized Windows corner card additionally requests account quota every minute through the installed Codex client's official `account/rateLimits/read` API. The Codex client handles existing authentication and communicates with its service; the HUD does not open credential files, create inference turns, or send conversation content for this lookup. Only remaining percentages, window lengths, reset timestamps and sync status are retained in the local runtime; account IDs, credit redemption identifiers and raw server errors are discarded. The quota lookup is enabled only for the corner card. The first source-overlay launch downloads public Qt dependencies into a private virtual environment; bundled apps need no dependency download. The browser interface communicates only with its own `127.0.0.1` HTTP service. HUD code does not read Codex `auth.json`, account credentials, or environment files.

The customized corner card also actively probes the two requested Clash Verge routes every 10 seconds, using local Mihomo named pipes or loopback HTTP only. It reads the local running controller configuration and keeps its controller authentication secret in memory, never in snapshots or errors. Only GET proxy discovery and delay requests are issued; routing, selection, subscriptions and configuration are not changed. Each delay request makes an HTTPS request through that route to `https://www.gstatic.com/generate_204` with a five-second test timeout. This endpoint sees the route's egress IP; no chat data is sent. Local snapshots retain only the two route names, selected chain names, delay/status/timestamps and up to 12 samples per route. The controller address, authentication secret, other proxies and raw response/error bodies are not persisted. This measures route latency rather than the Codex service's response time.

The corner card's small reset radar uses the public, anonymous Did Codex Reset API at `https://didcodexreset.com`: `/openapi/v1/status?lang=zh-CN&timeZone=Asia%2FShanghai` and `/openapi/v1/records/latest?kind=reset_completed`. It polls every 180 seconds, normally issuing two GET requests per round, or approximately 40 requests per hour. The provider's 60-request-per-IP-per-hour limit is shared with other clients using the same public IP, including a shared VPN exit. HTTP 429 responses and exhausted rate-limit budgets cause backoff using the provider's retry information. The site sees the connection's public IP and the fixed language/time-zone query; the HUD sends no account identifier, credentials, conversation content or local logs. It does not redeem reset credits or change the account. Codex Radar's complete API requires authorization and is not integrated in this version.

Public schedule and completion records are stored as normalized local runtime data. New schedules can produce tray notifications, with a further reminder ten minutes before an explicit time or the start of an estimated window. Completed events present on the first synchronization are not replayed as notifications. Event IDs and notification timestamps are retained only in local `runtime/reset-notifications.json` to suppress repeats across restarts; they are never sent to the public service. Date-only notices remain date-only, inferred times do not become precise arrival countdowns, and an absent schedule is shown as “暂无排期”. The account's official weekly reset is displayed separately when available. Public announcements do not confirm that this particular account has received additional quota; the authenticated official quota response remains the source for account availability.

It reads the `threads` table in a compatible local Codex `state_*.sqlite` database using SQLite read-only mode, session metadata and the optional `session_index.jsonl` title index. The Windows native HUD reads the selected chat's recent JSONL tail and the accessibility header of Codex windows. The macOS/Linux HUD reads a selected or explicitly latest-active chat without accessibility access. Historical statistics stream the selected chat's complete local rollouts, including resumed segments and archived logs. Explicit `--log` inputs are read only when supplied by the user.

The optional Qt strip stores derived state, binding and layout in a separate `overlay-runtime` subdirectory. A user-only local socket and instance lock handle repeat-launch recovery. Its browser service has the same loopback/token restrictions. These private files and all real conversation data are excluded from public packages.

Message-range selection necessarily indexes user messages in memory and displays matching excerpts in the local browser. It does not display assistant bodies. Up to three conversations' history indexes are kept in process memory; exiting the process releases them. Selected message excerpts are not written to the saved range result. Terminal `stats.py --messages` prints user excerpts to the user's terminal; other reports contain derived statistics. None of this data is uploaded.

The browser service binds IPv4 loopback only, chooses an available port, checks Host/Origin, and requires a random per-process token for data APIs. The token is passed in the URL fragment and sent in a local request header; no access logs, external assets, CDNs or trackers are used. Requests cannot name arbitrary file paths. Do not share the printed link or `dashboard.json`. An explicitly configured SSH forward carries traffic to a host chosen by the user; it does not expose a public web server.

Derived JSON in `%USERPROFILE%\.codex-token-hud\runtime` includes chat titles, IDs, model, token counts, timing, source file paths, recent thread metadata, refresh receipts and a confirmed range snapshot. Saved layout and optional settings are in the same data directory. The dashboard uses `~/Library/Application Support/CodexTokenHud` on macOS, or `${XDG_STATE_HOME:-~/.local/state}/codex-token-hud` on other systems. `CODEX_TOKEN_HUD_HOME` can override the data directory. These files stay on the computer but are private. Do not upload them, real rollout logs, database files, or screenshots containing chat text in bug reports.

The source repository excludes local settings, runtime data, legacy layouts, inspection extracts, downloads, and build artifacts. Packaging copies an explicit allowlist and checks the archive for prohibited private paths. Packaging downloads the official Python runtime over HTTPS and verifies its pinned SHA256; this is a developer build operation, not application runtime traffic.

Exiting the HUD ends its collector. A following watcher stays idle after a manual HUD exit until the active clients close and reopen. Disabling following removes this copy's watcher registration and lets it exit without closing a manually continued HUD. Uninstall also removes the desktop shortcut and preserves saved user data. If you want to remove the saved data too, disable following and exit the HUD first, then manually delete its data directory. The HUD does not delete or alter Codex chats.

The response chart uses up to 20 completed response durations and completion timestamps already derived from local logs. Only these numeric records are added to the local snapshot; chart rendering sends no requests and invokes no AI service.
